# Agent 命令接入与默认部署权限（v0.3.4）

此前命令只安装受限的监控 Agent；`agentOnly` 服务器没有 SSH 凭据，不能运行现有 Xray/sing-box 安装、节点和中转流程。单独隐藏权限提示无法解决问题。

## 新接入

服务器 → 添加服务器 → Agent 命令接入。在目标机 root 终端执行生成的命令：

1. 保持原有每台机器独立的 Agent 登记、hostname 和心跳。
2. 默认执行管理授权。缺少 SSH 依赖时，支持 apt/dnf/yum 安装 OpenSSH；不更改已有 SSH 登录策略或防火墙。
3. 每台机器生成独立 Ed25519 管理密钥，写入 root 的 authorized_keys，保留已有公钥，禁止该密钥进行 SSH 端口、X11 和 Agent 转发。
4. 通过 HTTPS 将管理密钥交给所属面板，面板固定 SSH 主机指纹并实际验证 root 公钥登录后，将原记录提升为可管理服务器。私钥在面板加密存储，不在日志或页面回显。
5. 服务器卡片提供“安装 / 更新内核”，可选 Xray 或 sing-box。安装仍需管理员确认，完成后使用“节点 / 中转”管理原有功能。更多安装类型继续通过连接设置配置。

这使用已有 SSH 运维通道。监控 Agent 不获得任意脚本执行接口，不需要为监控开放新端口；部署管理需要面板能够访问服务器原有 SSH 端口。独立 root 管理密钥意味着管理员能够管理机器，应仅接入信任的面板。

## 已接入服务器

旧版 Agent 没有远程执行能力，不能由面板升级凭空获取 root 权限。点击旧服务器卡片的“启用部署权限”，在对应机器 root 终端执行一次命令，再刷新列表。无需重新添加服务器，已有名称、分组和监控记录保留。

也可以重新执行原有效接入命令，补齐同样的授权。该操作幂等，不重复追加同一个密钥、不重复创建服务器。已撤销的接入令牌不能重放，但仍有效的每机 Agent 凭据可用“启用部署权限”命令补齐。

若 SSH 验证失败，监控仍保留，安装命令明确报告管理接入未完成，不宣称已具备安装权限。检查云防火墙、SSH 端口和 root 公钥策略；NAT 映射、自定义 authorized_keys 路径或无法从面板连接的网络，需要按现有 SSH 手动接入流程配置。当前补授权不建立反向隧道。

切换内核前会提示备份与清理原内核管理状态，不自动卸载另一种内核。安装/更新会按原有流程校验配置并重启对应服务。

## 凭据与验证

公开管理授权接口仅接受已完成命令登记且仍启用的每机 Agent Bearer 凭据；共享接入令牌、匿名请求和已撤销凭据均拒绝。只能提升当前凭据所属服务器，不接受任意目标地址。网络验证期间不持有全局 Agent 锁，提交时再次核对凭据与服务器状态。不同密钥、端口或指纹不能通过重复授权覆盖已设置的管理连接。

Agent 监控凭据与 SSH 管理密钥是不同通道。撤销监控凭据不会删除服务器上的 SSH 公钥；要彻底撤销管理，移除面板服务器记录并在该机 authorized_keys 删除带 `mx-panel-agent-服务器ID` 标记的公钥，清理 `/var/lib/mxioc-agent-management` 中的专用密钥。

## 验收

- Go 全量测试通过；新增真实 SSH 握手测试覆盖正确密钥、错误指纹、匿名、共享令牌、撤销、重复授权、加密存储、记录不重复和心跳身份保持。
- Xray 与 sing-box 安装任务使用新增密钥正确派发，并继续要求确认；远程脚本执行使用测试执行器，不对用户机器试装内核。
- race 专项通过。
- 管理授权脚本在隔离路径下验证配置读取、私钥请求、0600 权限和重复执行不重复添加公钥；未改生产 authorized_keys。
- 浏览器检查旧版授权命令、安装选择与取消，以及原有页面和编辑操作回归。

未在用户服务器上批量执行授权、安装 SSH 服务或安装代理内核。真实防火墙、NAT、软件仓库可用性仍以该机接入和安装日志为准。

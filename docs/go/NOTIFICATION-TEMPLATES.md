# Telegram 通知文本模板（v0.2.30）

入口：「设置 → 通知中心 → 通知文本模板」。可以为告警、恢复、订阅到期、服务器续费提醒及每日汇总统一添加面板名称、时间或说明。默认空白，保持原始通知文本。

例如：

```text
我的面板 · {time}
{message}
请登录面板查看详情。
```

## 规则与预览

- 模板最多 512 个 Unicode 字符；必须包含恰好一次 `{message}`，以保留原始事件正文。
- 可选一次 `{time}`，显示事件生成时间（UTC），不是重试时的发送时间。
- 允许换行和制表符；不支持其他变量、花括号或控制字符。不执行表达式、脚本或网络请求。
- 纯文本发送，不启用 Telegram HTML / Markdown 解析；正文内的变量形状不会被二次替换。
- 「预览模板（不发送）」使用监控异常、流量阈值、到期、恢复或日报的固定示例；不使用真实服务器信息，不保存、不入队、不发送 Telegram。
- 「恢复默认文本」清空编辑框，点击「保存通知设置」后生效。预览失败不会改动已保存模板。

模板作用于后台提醒和日报；续费按钮点击后的预览/确认/取消回复保持原来的固定文本。模板不是每种事件的独立正文编辑器。已有日报预览仍显示原始日报内容，需要查看统一样式时使用模板示例预览。

## 投递、记录与长度

告警去重、恢复判定、过期提醒取消使用原始正文，不受模板外观影响。第一次发送前生成并保存 deliveryText；后续重试使用同一文本和事件时间，通知记录显示实际尝试投递的文本。老记录没有该字段时仍显示原始正文。

发送文本采用保守的 4000 UTF-16 单位上限（Emoji 通常占两个单位）。超长时只截断正文，保留模板前后文本并附「内容过长已截断，请查看面板」。原始完整正文仍保留在通知事件记录中，管理 API 的 text 字段可读取。没有把超长消息拆成多次发送。

沿用现有通知配置变更行为：保存不同设置会取消待发通知，并使已有续费按钮失效；持续告警仍按原去重规则，不会仅因修改模板重新群发。保存模板不会自动启用通知或发送测试消息。旧 API 请求不带 textTemplate 时保留原模板，显式空字符串恢复默认。

## API 与验证

`PUT /admin/api/notifications` 新增可选 textTemplate；原有通知配置字段仍需按接口要求提交。仅管理员可修改。

管理员 `POST /admin/api/notifications/template-preview`，请求 `{"template":"我的面板 {time}\n{message}","sample":"monitor"}`；sample 支持 monitor、traffic、expiry、recovery、daily。返回 text、truncated 和 `sample:true`，不需要 Bot Token 或 Chat ID。

验证包括 Go 全量、通知/模板/续费回调专项 race、模拟 Telegram 429 后重试文本一致、权限、旧请求兼容、Unicode 长度、特殊字符及真实 Chromium 六主题四宽度。没有向真实 Telegram 会话发送测试通知，没有改动生产通知配置。

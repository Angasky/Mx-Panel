# 独立订阅域名（v0.2.46）

入口：设置 → 网站信息 → 独立订阅域名。填写已准备好的 `https://sub.example.com`，可选非默认端口；留空使用浏览器当前访问域名。

## 生效范围

- 订阅总览的展示、复制、下载、客户端专用链接与二维码。
- 订阅列表、客户端链接窗口、管理员查看用户授权订阅。
- 普通用户门户的复制、原始订阅和其他客户端下载。
- 自动识别链接、按服务器筛选的 URI 保留原路径与查询参数。

这是一项对外地址设置，不自动配置 DNS、证书、Nginx 或 Cloudflare。保存时不访问该域名，不会验证归属、连通性或证书。仅填写自己控制并已正确配置的域名，订阅路径包含下载凭据。不会更改管理地址、Agent、公开监控链接、节点服务器地址或后端 API 的相对 URL，也不让主控代替客户端抓取订阅。

原域名下的订阅地址仍直接有效，不重定向、不轮换令牌。配置错误时清空该字段即可恢复当前域名；“恢复默认外观”保留订阅域名，避免外观调整意外改地址。当前页面保存后更新总览/列表，其他打开的浏览器需重新加载页面；已经导入客户端的旧地址不会自动迁移，需要重新复制或扫码。

## 部署步骤

1. 为独立域名设置 DNS，准备受信任的 HTTPS 证书。
2. 配置其反向代理到同一 Go 服务的 `/sub/` 与 `/convert/` 下载路径，拒绝该域名的管理入口。示例见 [Nginx 订阅域名配置](../../deploy/nginx-subscription.conf.example)。替换示例域名和证书位置，执行 `nginx -t` 通过后再重载。
3. 使用一份测试订阅确认客户端能下载，再在网站信息保存域名；面板的“预览（不保存）”仅显示地址文字，不执行联网验证。
4. 使用 Cloudflare 时为订阅域名设计无需浏览器挑战的策略，保留管理域名的保护；本设置不能绕过 Under Attack 或验证码。保持订阅不缓存，不要设置 Cache Everything。若经过 CDN，需在反代层只信任其官方地址范围恢复真实 IP；否则 IP 白名单可能只看到 CDN 出口。

示例只允许 GET/HEAD，剥离管理 Cookie/Authorization，拒绝其他路径。订阅仍以 URL 中的令牌认证，原有有效期、额度、撤销、IP 白名单及浏览器过滤照常生效；域名不是额外的权限隔离。示例另外拒绝已有 `/sub/status-*` 监控端点与 `/sub/status/` 路径，避免通过订阅域名开放监控页面。

## 校验与兼容

仅接受 HTTPS DNS 域名，可带 1–65535 端口。去除末尾单个 `/`，域名转小写，443 端口省略。国际域名须用有效 Punycode。拒绝 IP/IPv4 简写、localhost/local/internal、账号、路径、查询、片段、空白及非法端口。不会解析 DNS，也不承诺域名永远指向公网。

配置保存在 `site-info.json`，订阅域名是公开信息，随 `/site-info` 返回。写入沿用管理员/同源验证、0600 原子保存及 revision 并发保护；旧 API 请求省略 `subscriptionOrigin` 时保留原值，显式空字符串清空。API 相对订阅路径保持兼容，第三方集成可自行结合公开 origin。网站信息读取失败时网页仍允许登录，链接暂使用当前访问域名。

验证覆盖规范化、恶意/非法地址、旧请求、并发版本拒绝、重启回读及原地址有效；真实 Chromium 覆盖保存回读、刷新时序、总览与专用链接/二维码、普通用户复制与下载、六主题四宽度。Nginx 示例通过隔离 TLS 反代测试：拒绝管理/监控与 POST、保留路径/查询/客户端标识/无缓存头、剥离 Cookie 和 Authorization。未配置真实新域名、签发证书或更改生产 DNS/Cloudflare 策略。

# 订阅安全与兼容（v0.1.25）

入口：管理员「设置 → 订阅安全与兼容」。先选择订阅，再修改开关。设置按订阅持久化，普通用户只能下载授权的订阅，不能修改共享订阅设置。保存后客户端必须更新订阅并重连。

## 安全与联网开关

以下开关作用于完整 Clash/Mihomo YAML，不是服务器内核设置。

| 开关 | 开启后的行为 | 影响与范围 |
| --- | --- | --- |
| STUN / WebRTC 防泄露 | 在规则开头添加 STUN 域名关键词及 UDP 3478–3481、5349、19302–19309 拒绝规则 | 可能影响语音、视频、游戏；不是所有 WebRTC 泄露的完整防护，其他端口、自建服务或浏览器本地地址暴露不能一概保证 |
| DNS 防泄露 | 客户端 DNS 经 ✈️ Proxy 的 HTTPS DNS 发送；不使用原 nameserver-policy 或直连 fallback；TUN 开启时劫持 TCP/UDP 53 | 代理不可用时 DNS 也失败；代理服务器地址与 DNS 引导解析仍刻意直连以避免循环依赖。应用自行发起的 DoH/DoT、未经过此配置的系统流量不保证被接管；不开启 TUN 时须由客户端将查询交给内核 |
| 国内域名使用真实 IP | 在 fake-IP 过滤中加入 GEOSITE,cn,real-ip | 兼容部分国内 App；不新增路由直连规则。DNS 防泄露开启时，真实 IP 仍通过代理 DNS 查询 |
| 允许 IPv6 | 设置配置 ipv6 与 DNS ipv6 | 关闭不代表操作系统 IPv6 已被防火墙阻断；客户端须避免绕行 |
| 基础广告拦截 | 对已有基础广告组优先选择 REJECT | 无对应组时不安装新规则，可能误拦截业务请求 |
| 强力广告拦截 | 对已有强力广告组优先选择 REJECT | 更容易误拦截，异常时可关闭 |

关闭 STUN 开关只去除四条已知默认规则，不删除用户另写的其他拦截规则。关闭 DNS 防泄露表示不再应用强制代理解析覆盖，恢复原 YAML 的 DNS；不删除原文件自定义设置。广告开关调整默认策略顺序，客户端若保留旧的选择，还需手动选 DIRECT/REJECT。

国内真实 IP 兼容原 rule 与 blacklist 模式；自定义 whitelist 模式不自动改写，启用时会明确报错。常见 blacklist 域名规则转换为等效过滤条件；原始 YAML 保留。

## Xray / sing-box 实验性兼容

- **Xray 完整 JSON 导出**：默认关闭，开启后订阅总览增加可用的 Xray 导出。每个兼容节点生成一份完整配置，SOCKS 10808、HTTP 10809，仅监听 127.0.0.1；导出为配置数组，需支持 Xray 自定义配置导入的客户端。链式节点与不兼容参数列出跳过原因。原有 Xray 主备导出独立保留。
- **sing-box 客户端导出**：保留既有入口的默认开启状态，可以关闭。含本地 mixed 2080、手动选择组和兼容节点。标注实验性，不保证所有客户端版本都支持。

两种导出不自动翻译 Mihomo 策略组、完整路由、DNS或上述防泄露设置。裸 vless/vmess 等链接和其他客户端基础节点导出同样不携带这些开关效果；须在对应客户端另行配置。开关不安装、更换或重启远端 Xray/sing-box。

## 持久化与恢复

开关保存在 profiles.json 当前订阅的 clientOptions 字段。只在输出订阅时生成覆盖后的配置，原始 YAML 不被改写；管理员原始配置编辑器看到的仍是源配置。点击「恢复原配置」删除该订阅覆盖，下载内容恢复原 YAML。

升级不会强制开启 STUN、DNS 防泄露或 Xray 实验导出。未保存覆盖的订阅按原配置输出；已有 sing-box 导出保留。复制/新建订阅默认不继承原订阅的安全覆盖，需单独设置。

## 验证

覆盖持久化、订阅隔离、原始 YAML 不变、缓存隔离、关闭/恢复、无代理组拒绝启用 DNS 防泄露、损坏/不完整请求和跨站操作拦截。真实浏览器验证保存、下载内容、Xray JSON 下载、禁用 sing-box、恢复配置、普通用户禁止读写以及六主题三宽度布局。

生成的全开 Clash/Mihomo 配置通过 Mihomo 校验，Xray/sing-box 配置通过本地内核检查。未完成所有手机系统或客户端版本的实机验收。

## v0.1.26：Android Clash Meta + Chrome

新增「填入 Android Clash Meta + Chrome 推荐配置」，只填表，保存后才生效。选择国内兼容 DNS、国内真实 IP、Chrome UDP 代理，关闭 IPv6 与默认广告拦截；不会自动改变已有订阅。旧配置与旧客户端保持原来的严格模式，已有选择不会被悄悄改成较宽松模式。

- **DNS 国内兼容**：CN/private 域名通过阿里/腾讯 HTTPS DNS 直连解析；其他查询通过代理 DoH，代理失败不回退到直连。国内查询是有意允许的隐私例外，国内解析器会知道这些域名与直连出口；不能称全部 DNS 都隐藏于代理后。实际分类依赖 GeoSite 数据，漏收域名或特殊 App 自建 DNS 仍可能需要单独适配。
- **Chrome UDP 代理（实验性）**：将进程名为 com.android.chrome 的 UDP 规则放在最前，转发到 ✈️ Proxy；保留其他 App 的原规则，不再附加全局 STUN 拦截。这是减少 Chrome WebRTC UDP 绕行风险的兼容选项，不是 STUN 协议识别或完整的 WebRTC 防泄露保证。Chrome 的 QUIC/国内视频等 UDP 同样会代理，可能降低速度或影响地区判定。
- 必须在 Clash Meta 中选择规则模式，允许 VPN 接管 Chrome，不能将 Chrome 排除。应用包名识别、UDP 转发需要在实际 Android/Clash Meta 版本中验证；不能仅凭生成配置或桌面内核校验判定手机有效。
- ✈️ Proxy 必须选支持 UDP 的实际代理节点，不得选 DIRECT，也不能选择最终回落到 DIRECT 的策略组。内核不支持该节点 UDP 时，通信可能失败。其他端口、TCP TURN、本地地址候选和未进入 VPN 的流量不在该规则的绝对保证范围内。
- Chrome「使用安全 DNS」建议关闭，使浏览器查询交给 Clash；Android 私人 DNS、自带 DNS 和 VPN 应用绕过选项也需检查。不要以加密 DNS 的供应商所在地单独判断泄露。
- 使用浏览器 WebRTC 检测时核对公开候选 IP 是否出现真实直连出口，并在 Clash 连接日志确认 Chrome UDP 使用代理。国内 App 直连时服务方本来就会看到直连 IP，不能同时要求对该服务隐藏地址。

本次环境没有 Android 手机，因此不宣称手机应用识别、WebRTC 实际候选和所有国内 App 均已实机通过。

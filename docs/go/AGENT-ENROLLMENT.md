# 复制命令接入服务器（v0.2.51）

入口：服务器管理 → 复制命令接入 Agent；“添加服务器”表单也有 Agent 接入入口。

1. 通过可信 HTTPS 域名访问面板，默认勾选“长期多服务器令牌”，生成并保存命令，无需填写服务器名称。
2. 将同一命令复制到各台目标服务器的 **root 终端**执行，自动使用各自 hostname 命名。无需向面板提供 SSH 密码、私钥、IP 或主机指纹。
3. 安装程序下载并校验固定 Agent v0.1.35，自动登记服务器、保存 0600 配置并启动 systemd 服务。
4. 页面每 5 秒刷新接入记录。脚本必须收到面板的已认证心跳确认，才打印“接入成功”。服务器管理中出现“Agent 免 SSH”卡片，可打开硬件监控。历史记录需在监控页面按需开启。

支持 Linux amd64 / arm64、systemd；需要 curl、tar、sha256sum、flock 和标准基础工具。只需要 HTTPS 出站访问，不新增入站监听端口。网络必须能下载 GitHub Release 并访问面板；面板 Agent 路径不能被浏览器验证码拦截。IP / 自签 HTTPS 面板暂不提供命令生成，请先准备可信 HTTPS 域名。独立订阅域名不用于 Agent。

## 权限与范围

首次接入仅启用现有资源采样 Agent：CPU、内存、磁盘、网速及已有采样指标。WebSocket 优先，失败回退 HTTP。未提供服务 targets，因此没有代理配置修改、服务重启或任意命令权限，不修改已有 Xray/sing-box、节点、路由或防火墙。

此方式将服务器登记为 `agentOnly`、`installType=agent`，不会伪造 SSH 密码或指纹。连接设置、节点部署、中转、SSH 诊断/升级不作为已具备能力展示；后端也拒绝通过 SSH 操作或覆盖此记录。普通 SSH 服务器添加和探针同步保持原流程。需要本机授权的 Agent 配置管理时可在 Agent 页面生成配置，下载到目标机并按说明重新安装；这仍不等同于完整的非 SSH 节点管理流程。

登记 IP 来自请求来源（仅信任已配置本机反向代理覆盖的 X-Real-IP），可能是 NAT 或 CDN 出口，仅作来源展示，不作为节点地址或用于自动远程连接。服务器改名/更换地址和无 SSH 全套节点管理仍需后续实现。

## 长期令牌与恢复

- 默认长期多服务器令牌，没有 30 分钟限制；同一命令可用于多台机器，每台按随机安装实例标识登记。相同 hostname 或出口 IP 不会合并不同机器。
- 每台机器取得独立正式 Agent 凭据，日常上报不使用共享接入令牌；面板只保存凭据摘要。可以在单台 Agent 管理中独立撤销或轮换。
- 撤销共享接入令牌阻止之后的登记和安装重试，已接入服务器继续用各自凭据上报。若要停用服务器，需要撤销该服务器 Agent 凭据。旧命令不能恢复已撤销、轮换或已移除的服务器。
- 同一实例重复运行原命令、安装失败后重试、面板重启后重试不会创建重复记录。安装状态 `/var/lib/mxioc-agent-enroll/<令牌ID>` 以 0700 保留，包含 0600 的实例标识及已安装配置；不要跨机器复制该目录。
- 命令只在生成时显示，请保存以便多机复用。关闭页面后无法取回原令牌，可撤销并生成新令牌；不会影响已登记服务器。
- 取消“长期多服务器令牌”后仍可生成旧式单机命令：有效期 30 分钟，仅一个实例可用；自动命名受下面的设置开关控制。旧命令不会被自动放宽为长期令牌。
- 令牌不放在请求 URL 或 curl 参数中；安装脚本用 0600 临时请求头文件发送。整个复制命令本身含接入凭据，可能保留在终端历史中。

不覆盖已有 Agent 配置/二进制/标准或非标准位置服务。首次安装失败会清理本次新建的配置、二进制和服务文件，保留面板登记与恢复状态。若服务已安装但心跳未确认，保留服务供排查，明确返回失败，不冒充在线；查看 `journalctl -u mxioc-agent`。超过有效期后应核查旧记录与本地配置再重新生成，避免盲目安装多个记录。

移除服务器或撤销凭据不卸载目标机程序，需在目标机自行停止 `mxioc-agent.service`。已有 Agent 接入没有 SSH 回退凭据，撤销后不会继续采样。SSH 批量升级不列出这些服务器，升级需要在服务器本机进行。

## 接口与验证

管理员 `/admin/api/servers/agent/enroll`：POST 生成、GET 查看状态、DELETE 撤销长期令牌或待接入单机命令。管理认证、同源、HTTPS 检查沿用面板。

公开 `/sub/agent-install.sh` 只返回无凭据安装脚本；`POST /sub/agent-enroll` 只接受单个 Authorization Bearer 接入凭据、登记 ID 和随机安装实例标识，拒绝 Cookie 或 URL 令牌替代。仅返回该服务器的最小 Agent 配置，不授予面板管理权限。最多 50 个活跃接入令牌/待登记项，令牌及 Agent 记录总计最多 1000 项。沿用 agents.json 原子落盘和锁，部分写入失败可以由同一实例重试。

验收包含：匿名/普通用户/跨站拒绝、HTTPS、过期/撤销/轮换/移除、另一个实例重放拒绝、并发及重启幂等、无明文令牌落盘、服务器只读权限、真实固定版本 Agent 的 HTTPS/WebSocket/HTTP 上报；浏览器生成/撤销/状态/卡片与六主题四宽度。安装脚本使用隔离路径及模拟 systemd 验证成功、已有安装保护、校验失败、安装失败清理、无心跳不报成功。未在用户其他生产服务器执行安装或修改其服务。

## 自动读取 hostname（v0.2.49）

入口：设置 → Agent 自动接入，或服务器管理 → 复制命令接入 Agent。开启“自动检测主机名”并保存后，新生成的单机命令无需填写服务器名称。此设置默认关闭；长期多机模式始终自动读取 hostname。

目标机执行命令时读取 `hostname`（失败时使用 `uname -n`），将其上报为服务器名称；不会修改机器本身的 hostname。开关状态在生成命令时固定，已有命令与已登记服务器不受影响。同一安装实例重试、后续心跳不覆盖已确定的名称。

自动名称接受 1–253 位 ASCII 字母、数字、点、连字符和下划线，保留大小写；缺少或非法 hostname 时拒绝自动登记，需要使用最新安装脚本。关闭开关后恢复 1–60 字符的手填名称。设置保存需要管理员权限和当前版本，过期页面保存返回冲突。

仍需在目标机主动运行安装命令，并使用有效接入凭据；该开关不会扫描公网或允许匿名注册。安装环境额外需要标准 `base64` 工具。Agent 保持 v0.1.35，权限范围仍为硬件监控。

本版验证：Go 全量、接入专项 race、真实固定版本 Agent 上报、隔离安装脚本五类场景、Chromium 设置保存/重载/自动命名/恢复手填，以及六主题四种宽度。未在其他用户生产服务器执行安装。

## v0.2.51 安装修复与验证

修复发布包清单校验依赖服务器语言环境的问题：已验证 SHA256 的包仍可能因英文等 locale 排序规则被误拒绝，现在强制使用 C 排序。继续校验固定 v0.1.35 包的 SHA256 与精确文件清单。

已使用真实发布包在 en_US.UTF-8 下复现旧排序，并验证修复后的安装、重复执行、已有安装保护、损坏包拒绝、安装失败回滚、无心跳拒绝报成功。另通过多实例独立凭据、跨一年不失效、同 hostname 不合并、并发/重启重试、单台撤销不能绕过、共享令牌撤销不影响已有凭据，以及六主题四宽度浏览器验收。安装流程使用隔离路径和模拟 systemd，未在用户其他服务器执行安装。

# 批量启用节点证书验证（v0.2.26）

管理员在「节点管理 → 我的节点」勾选节点，展开「批量操作」，点击「启用证书验证」。预览列出需要修改的节点数量和名称，再确认保存。一次支持 1–500 个明确选中的节点；没有选择时按钮禁用，不自动处理全部节点。筛选只改变显示范围，已经选中但被筛选隐藏的节点仍属于选择范围；可先取消选择再使用「选择当前结果」。

此操作将当前订阅所选节点的顶层 `skip-cert-verify: true` 改为 `false`；不存在该字段或已经为 `false` 的节点无需修改。保留节点地址、凭据、TLS 开关、协议、SNI、策略组和扩展字段，不修改远端服务端证书。字段类型错误或任一节点不存在时整批拒绝。

启用后，自签名、过期或主机名不匹配的服务端证书可能导致客户端连接失败。Reality、公钥固定及插件内部 TLS 配置不由该按钮处理；此操作不保证所有协议都执行传统 CA 证书验证。客户端需要更新订阅后才会使用新配置，上游再次导入覆盖节点也可能重新带入原值。

预览不写入；确认绑定订阅内容、元信息和所选节点，期间发生变更需重新预览。沿用主备链路保护、配置备份、镜像写入及失败回退。备份可在「账号与备份 → 配置备份与恢复」查看。普通订阅用户不能调用此管理接口。

接口：`POST /admin/api/nodes/certificate-verification`，`X-Profile` 指定订阅。

- 预览：`{"action":"preview","names":["节点 A"]}`。
- 确认：同一 names，action 为 apply，并带预览的 revision 和 `confirmed:true`。
- 响应仅包含 changed、unchanged 名称列表和 revision，不返回节点地址、密码或 UUID。

验证覆盖预览无写入、选择变更、并发提交、过期预览、权限/来源限制、主备保护和镜像异常；隔离后端与真实 Chromium 验证选中/预览/保存及六主题四宽度。未修改生产用户订阅测试，不代替客户端实际 TLS 握手验收。

# 双服务器中转与自定义 SNI

适用于 v0.3.23 起。入口：服务器节点 → 添加中转，或链式代理 → 选择托管服务器创建中转。

## 创建方式

1. 选择入口服务器，独立设置入口协议、端口和 SNI / 证书。
2. 落地来源选择“选择服务器，创建新落地节点”，设置另一台服务器及协议；也可选已有订阅节点，或粘贴分享链接。
3. 确认创建后，先创建落地并绑定当前订阅，再创建入口出站与专属路由。无需先手工准备订阅节点。

独立 Xray / sing-box 使用现有托管入站模板（Reality、VMess、Shadowsocks、TLS 与 WS/gRPC 等），Web 面板入口支持 Reality、VMess TCP。UI 按两端内核过滤组合：Xray 入口不提供 HY2/TUIC 落地，sing-box 入口不提供 XHTTP 落地。HY2/TUIC 新建向导仅在 sing-box 上提供。远端实际内核仍会在写入前验证完整配置，版本不支持时拒绝应用。

TLS 在此向导填写该服务器已有证书与私钥的绝对路径，可先在证书管理申请；Reality 使用通过测试的第三方 SNI，不需要自己的证书。不会把第三方 SNI 当作自己的证书。

## 失败和资源归属

两端是顺序执行的独立操作，不宣称跨服务器原子事务。落地成功而入口失败时，落地节点保留，可在同一窗口继续核对，复用原操作标识；关闭窗口不再启动下一阶段。在途请求可能已完成，请在服务器节点核对。刷新或关闭后，也可选择已创建的落地节点继续，勿重复创建落地。

落地是独立托管节点。删除服务器中转会清理入口关联路由，不自动删除落地；两端绑定同一订阅时均计入订阅总用量。创建会重启对应内核。不会修改已有中转协议或已有节点 SNI。

## SNI 与测速

参考 [Teminuosi/3x-ui 的候选表](https://github.com/Teminuosi/3x-ui/blob/b70a4bb/frontend/src/models/reality-targets.ts)。该版本从 7 个预设中随机选择，不是现场完成完整扫描。本项目沿用排除 AWS/CF 的设置，引入其中 5 个非 AWS 域名。候选不代表已验证可用；例如本轮实测 AMD 未通过参考服务器 TLS 检查，其他 4 个通过。

扫描窗口顶部可输入自定义域名或使用候选建议，单独验证当前服务器 TLS 1.3 和实际 Reality 握手。固定库在参考服务器验证后复用；当前服务器只做 TCP 测速，一次 SSH 下发、每波最多 8 个连接。20 个站点本轮实测耗时约 2.72 秒（参考机器和当时网络），不是所有网络的时延承诺。

默认隐藏 Google/YouTube/GitHub/Wikipedia 等常见受限域名，可手动显示全部。海外服务器验证与国内 GFW 可达性是不同检查，不承诺候选在所有中国运营商线路可用。现有配置不因过滤而改变。

## 验证

Go 全量测试与专项 race；扩展模板的创建、断线恢复、重试、删除和身份保护；真实 Xray / sing-box 配置校验；TCP 批次乱序、缺失、重复编号、非法目标与 shell 调度测试；隔离浏览器双服务器选择、同机拒绝、部分失败重试、关闭后停止下一阶段、自定义 SNI、TLS 和六主题四屏宽验证。SNI 在参考机器实测；未在用户机器批量创建或重启真实业务节点。

# Komari 探针服务器同步（v0.1.36）

入口：左侧 **服务器管理 → 同步探针服务器**。适配已有 Komari 管理 API（client/list、task/exec、task/result），参考本机 Komari 项目接口实现，不要求修改原探针。不能从公开探针页面获得服务器管理权。

## 使用

1. 填入探针根地址（例如 `https://monitor.mxioc.com`）及 Komari 管理 API Key，保存后读取服务器列表。API Key 使用面板凭据密钥加密保存，不回显；无需提供每台服务器的 SSH 密码。
2. 对目标服务器选择「授权并接入」，确认 SSH 端口和独立 root SSH 公钥授权。
3. 原 Komari Agent 执行一次授权任务。任务完成后点击「核对接入结果」：面板将 SSH 主机指纹与原探针返回值对照，并实际验证独立密钥登录，成功才加入服务器列表。
4. 在服务器管理中选择相应内核类型及安装/已有服务接入模式，再使用现有节点、监控、证书等功能。同步不会自动安装或覆盖原代理内核。

需要 Linux、root 权限 Agent、正在运行且允许 root 公钥登录的 SSH、标准 `/root/.ssh/authorized_keys`，以及 Mx-Panel 到服务器公网 SSH 端口的网络可达性。不会自动开放防火墙、修改 sshd 配置或重启机器。非标准 SSH 配置会拒绝授权，不能把有探针连接等同于有 SSH 管理权限。

## 两边如何管理

原探针和原 Agent 保持运行，仍可从 Komari 监控与执行操作。Mx-Panel 通过自己的独立 SSH 密钥管理同一台主机；即使探针暂时断连，已接入服务器仍可通过 SSH 管理。两边没有跨应用写锁，不应同时编辑相同服务配置。

这是「复用探针身份并授权接入」，不是双向配置复制。刷新页面会重读探针列表；服务器接入后的地址、名称、内核配置仍由 Mx-Panel 自己维护，不会因原探针删改记录而自动删除节点或替换主机身份。已在本面板登记的同 IP 服务器拒绝重复接入，继续使用现有记录。

## 安全与恢复

- 每台服务器生成独立 Ed25519 密钥；只发送公钥至原 Agent。私钥不进入 Komari 任务日志、浏览器或 Git；成功后加密存入服务器凭据。
- 公钥添加保留已有授权项，重复执行同一脚本不会重复添加；拒绝符号链接路径。页面显示授权密钥指纹用于核对。
- 连接探针仅允许公网 HTTPS，不跟随跳转；管理 Key、私有备注和 Agent Token 不会出现在列表输出。普通用户无权限读取/操作此功能。
- 派发前保存意图和密钥。派发结果未知时不盲目重试：从原探针任务记录复制任务编号，使用「恢复任务关联」，校验任务目标与完整公钥脚本后重新关联。
- 已确认失败的授权任务可在修复原因后重试，复用原密钥。未确认任务不能自动重发。SSH 端口错误应先核对原任务及服务器配置。
- 探针离线或 API Key 失效时保留已接入记录，设置页仍可修改 Key。已有接入记录时不允许直接把来源地址换成另一个探针。
- 删除面板服务器记录、停止面板或更换探针 API Key，**不会撤销已添加的远端公钥**。需停用访问时，在远端 `/root/.ssh/authorized_keys` 按页面展示的指纹删除对应 `mx-panel-probe-sync` 公钥；不要删除其他面板或管理员的授权项。
- Komari 若要求额外二次验证或禁用了远程执行，接口会拒绝，不绕过原权限设置。

## 验证范围

隔离 Komari HTTPS 模拟接口 + 本机独立测试 SSH 监听验证授权、指纹和密钥登录、加密登记、重复接入拒绝、失败重试、未知任务恢复、权限隔离及断网保留设置。临时目录执行授权脚本验证保留原密钥、重复执行和符号链接拒绝。浏览器覆盖折叠菜单、记忆展开状态、精确高亮、六主题/三种宽度。

没有向真实探针 Agent 派发测试命令，也没有自动授权任何生产服务器。不同 Komari 版本、二次验证策略和远端 SSH 配置仍须实际接入时验证。

## v0.1.37：一键批量接入

选择「全选未接入 / 批量接入所选」或「一键接入全部未接入服务器」，一次确认即可创建后台批次。默认 SSH 端口为 22，支持逐行覆盖端口；最多选择 200 台，总接入数仍限 200 台。

队列约每 3 秒推进一次，最多同时保留 3 台待验证任务；自动派发公钥授权、查询原探针任务结果、核对主机指纹与密钥登录，成功后登记。某台失败不阻塞其余服务器，5 分钟未完成核对会标记超时，仍可单独检查结果。页面每 5 秒更新本地批次状态，关闭网页不会停止后台任务。

重复提交拒绝创建第二个活动批次。停止只停止后续派发和自动核对，已派发的远端授权任务不强制终止。重启后继续安全的排队和已知任务核对；处于派发中但没有可确认任务编号的条目标记未知，不重复发送授权。失败/未知条目按上一节的恢复流程处理。

## v0.1.37：复用原探针监控

所有通过探针接入的关联服务器（包括 v0.1.36 已接入的记录）自动从 Komari 读取监控：

- 硬件与实时网速：`/api/recent/{uuid}` 中时间最新的有效上报，使用原上报时间，超过 90 秒标记过期；同来源/凭据/服务器的请求合并，内存缓存 10 秒。
- CPU 型号、系统等基础资料：共享服务器清单缓存 5 分钟。
- 最近 24 小时 CPU、内存、网速历史：读取 `/api/records/load`，请求缓存 60 秒，最多显示 2880 个已有时间点。保留周期和采样间隔由 Komari 决定。
- 原探针不可用时显示错误/过期，不回退 SSH 采样，不把缺失数据显示成正常在线。普通用户无监控管理权限；已显式配置的监控分享也使用同一来源与缓存。
- Mx-Panel 后台跳过这些服务器的 Agent/SSH 历史采样，不重复写历史数据库；旧本地历史文件保留但不再更新。未关联的普通 SSH/Agent 服务器仍按原设置运行。
- 原探针没有提供的每核 CPU、逐网卡/挂载点明细不额外采集。30 天流量、计费周期与监控告警/日报继续在 Komari 查看；本面板不把降采样的网速曲线推算为完整流量账单，也不使用旧本地记录发送新的采样告警。服务器续费提醒等非采样通知保留。
- 此次不会自动卸载或停止用户独立安装的 Mx-Panel Agent。如果同一服务器另有旧 Agent 主动上报服务，它仍按自己的配置运行；可确认无其他服务管理用途后单独停止。新批量接入不会安装第二套 Agent。

读取原探针 API 仍产生少量请求开销；节省的是重复的远端采样、额外 Agent 部署与本地历史存储，不是完全零网络请求。

验证增加：完整批量 SSH 接入、3 个待验证任务限制、停止/重启未知状态、防重复派发、权限隔离；20 个并发请求合并为一次近期数据请求、历史缓存、本地后台跳过采样、原时间戳保留、错误身份/未来时间拒绝，以及浏览器批量确认/端口覆盖/自动进度/只读探针历史/过期提示。

## v0.1.38：SSH 接入兼容修复

根据真实失败任务修复以下问题：旧脚本遇到关闭公钥或端口不同会直接退出、没有具体错误；优先使用 IPv4 且不尝试 IPv6；要求 Agent 必须为 root。

- 新授权脚本返回实际 sshd 端口与明确错误码，不因用户填写 22 而拒绝不同端口。验证时先尝试填写的公网端口，再尝试上报端口；IPv4 不通会尝试原探针 IPv6。所有候选地址仍必须匹配该任务返回的 SSH 主机指纹并通过独立密钥登录。
- Agent 为普通用户且已有免密码 sudo 时，通过 `sudo -n` 执行授权；不索要或保存 sudo 密码。不自动解除 `PermitRootLogin no`。
- 「批量重试失败 / 超时」复用原密钥，只重新派发已确认失败任务；已授权/超时服务器只核对连接。未知任务不重发，可使用「自动找回授权任务」精确匹配原服务器、授权脚本和公钥。
- 「开启公钥登录并重试」和对应批量按钮需要明确确认。仅对关闭公钥登录的服务器备份 `/etc/ssh/sshd_config` 到 `/var/backups/mx-panel-ssh/`，前置 `PubkeyAuthentication yes`，校验后重载 systemd 的 ssh/sshd 服务。不关闭密码登录，不解除 root 禁止策略；校验/重载失败时恢复原配置。非 systemd 或自定义授权路径需人工处理。
- 「修改公网 SSH 地址/端口」用于共享 NAT、端口映射等情况，只更新待接入记录；随后仍执行指纹验证。不扫描所有端口，不把探针报告的出口 IP 当作一定可用的 SSH 地址。
- 无法连接时显示当前具体原因；单台重新核对成功后同步修正批次结果，不一直保留旧失败标签。

测试覆盖：不授权修复时不改 SSH 配置、明确授权开启公钥、原密码登录保留、重载失败回退、sudo 和非默认端口、替代地址验证、错误指纹拒绝、旧任务恢复与浏览器修复确认。测试使用临时文件与模拟 systemd；实际远端修复按用户选择执行。

## v0.1.39：重新同步 IP

已接入服务器现在支持单台「重新同步 IP」与「重新同步已接入服务器」后台批次。读取原探针同一 UUID 的最新 IPv4/IPv6，使用已保存的 SSH 端口、原主机指纹与原密钥验证登录，然后仅更新管理地址。失败保留旧地址，并显示原因；不会重复授权、安装内核、删除节点或重新创建服务器 ID。

页面分别展示探针当前地址、本面板地址和最近同步时间。现有部署任务或待核对用户变更、并发配置修改、重复地址记录会阻止更新。NAT 映射、SSH 端口变化或重装系统导致主机密钥变化，不能仅凭探针上线自动覆盖身份。

此次同步的是服务器管理 IP；已生成节点的连接地址、域名和订阅内容不自动改写，请按实际代理监听与公网映射核对节点地址。监控本来就按探针 UUID 读取，不受管理 IP 改变影响。

## v0.1.40：节点发现、硬件信息与地球位置

修复探针接入后按默认 Xray 路径读取所有服务器、导致现有 X-ui / sing-box 节点获取失败的问题。尚未接管的探针服务器在打开节点页时，通过已核对指纹的 SSH 只读发现常见配置及运行中 Xray / sing-box 的绝对配置路径，展示协议、端口、标签和来源；不会安装内核、导出用户密钥或修改节点。未发现配置和未能解析的配置分别提示。容器内部、JSONC、其他内核及未运行的非标准配置仍需手动接入。

这些节点是**已发现、尚未接管**状态，不用于自动订阅分配、删除或到期清理。需要管理时在“连接设置 / 接入已有内核”选择真实类型，按已有接入流程验证。已经由本面板管理的节点继续使用原流程。探针同步不等同于接入原 X-ui 账户。

硬件详情复用探针已有 CPU 核数、IPv4 与 IPv6；区分探针报告地址和逐网卡地址。探针不提供每核使用率及逐网卡明细，不额外增加 SSH 周期采样。上游返回 HTTP 429 时提示限频，不再误导为 API Key 错误。

3D 地球优先使用手动坐标；未填写时使用探针国家/地区的近似参考坐标，标明精度，不能视为机房地址。同地域服务器可在地球下方逐台选择；未知地域列出缺失名单，不虚构位置。只向管理员返回探针地域，不改变监控分享的公开设置。

这是一份差异记录，不是“与参考项目全部等价”的声明。仍有架构和产品能力差异：现有 SSH 可视化流程全面替换、数据库切换、三网回程及参考项目商业授权等没有实现。

## 验证

暖橙主题经过真实 Chromium 页面、弹窗与 390px 手机布局检查；协议筛选与 sing-box 下载经过真实 Go 后端浏览器验证。生成的 sing-box 配置通过本地 1.14.4 内核 check，未代表所有第三方客户端版本均完成实机连接验证。

多用户经过两个不同账号的真实浏览器登录、订阅隔离、手机布局和管理员管理表单验证；后端测试覆盖管理接口越权拦截、授权变更/禁用/重置/删除后的会话撤销、重启持久化、会话到期与损坏数据拒绝认证。

历史监控与订阅计费分开：只有启用后的有效采样区间计入网卡流量。重启、计数器回退、网卡变化、超过 90 秒的采样间隔、失败样本与跨 UTC 日期区间不计算流量差值。不会伪造安装前或停用期间的历史。


## 2026-11-12 重新核对的差异

本次再次读取妙妙屋X GitHub 默认分支 README（含发布历史），不能把发布说明当作已完成实机等价验证。除上表外，仍有以下缺项或部分实现：

| 项目 | 当前差异 |
| --- | --- |
| SQLite / PostgreSQL 与数据库备份恢复 | 未实现数据库驱动切换；目前使用文件持久化及文件备份 |
| Docker Compose / OpenRC 部署 | 当前官方安装包面向 Linux + systemd；没有对应的正式 Compose / OpenRC 安装流程 |
| Telegram 通知中心 | v0.1.21 新增监控连续采样失败/恢复、订阅流量阈值、订阅到期与服务器续费提醒；v0.1.22 补齐网卡观测流量日报、TCP 失败比例/ICMP 丢包和延迟告警；仍缺“我已续费”回调，日报不等于订阅逐日计费；采样状态不等同真实代理上下线 |
| Agent 全流程管理与滚动升级 | Agent 已有配置和生命周期管理，但可视化入站/出站/部署仍依赖 SSH；没有先升级一台验证再批量滚动升级的编排 |
| 三网回程 | 未实现运营商回程识别、线路分类和相关展示；TCP/ICMP 探测不能替代 |
| 独立探针站定制 | 已有公开监控和手动坐标地球；未具备自定义标题/Logo、禁用原登录页等完整独立探针配置 |
| 服务器周期流量与外部订阅聚合 | 已有网卡历史和订阅额度；没有与参考项目等价的服务器计费周期/限额与外部机场流量聚合趋势 |
| 用户多套餐与拼车发布 | 可授权多个订阅，每订阅可套套餐；没有完整的同用户多套餐产品及官方拼车页发布集成 |
| 客户端配置转换 | 格式入口齐备，部分仅基础节点与手动组；没有把全部规则/策略组/链路等价转换到每种客户端，部分缺少客户端实机验收 |
| 在线连接 | 已实现托管独立 Xray 用户在线 IP；3x-ui、sing-box、专属端口及外部节点尚无统一连接统计 |
| 证书验证 | 三家 DNS 提供商入口已有；没有真实账户环境完成公网签发/续期全链路验收 |
| 商业许可证体系 | 未实现参考项目的许可证、Guard 签名和商业套餐发布体系；不属于同一授权生态 |

已具备而不应再列为缺项：多用户订阅权限、Agent 三种连接模式、SSH 自动安装 Agent、地域与续费记录、公开监控/API/WebSocket、TCP/ICMP、手动坐标 3D 地球、常见客户端格式导出。


## 当前补齐顺序（v0.1.22）

1. **已交付第一批：通知中心**。管理员设置 Telegram、按需开启，配置阈值，查看投递记录；加密凭据、持久化去重、限流退避，详见 [通知说明](NOTIFICATIONS.md)。
2. **已补齐第二批：通知扩展**。前一 UTC 自然日网卡观测流量汇总、管理员只读预览、TCP/ICMP 延迟与失败/丢包告警及恢复。下一优先级为续费回调与 Agent 分批升级。
3. **随后：使用与部署能力**。独立探针标题/Logo、Docker Compose/OpenRC、服务器计费周期与外部订阅流量聚合。
4. **长期架构项**。数据库驱动切换、跨内核连接统计、全部客户端规则/链路转换、三网回程；需要单独设计与实机验收。商业授权体系暂不列入优先项。

通知测试覆盖配置权限、凭据脱敏/加密、连续失败与过期采样、恢复/去重/重启、流量与到期条件、Telegram 成功/429/403/无效响应与重试队列。浏览器覆盖六主题、三种宽度、保存/清除 Token、普通用户读写禁止。测试仅使用隔离数据和模拟 Telegram，未向真实会话发送消息。

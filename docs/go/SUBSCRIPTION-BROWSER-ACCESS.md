# 浏览器订阅访问控制（v0.2.29）

入口：先选择订阅，再进入侧栏「订阅管理 → 浏览器订阅访问」，或「设置 → 浏览器订阅访问」。默认关闭，不改变已有客户端更新方式；每份订阅独立保存。

开启「禁止浏览器直接下载此订阅」后，原始 `/sub/` 与全部 `/convert/` 下载路径统一检查请求特征。识别为浏览器时返回 403，不发送节点、额度、订阅名称或附件响应头；HEAD 不发送正文。错误响应禁止缓存。未知订阅令牌仍返回 404，原 IP 白名单、到期、额度与撤销检查仍生效。

## 识别范围与限制

满足以下任一条件视为浏览器请求：

- Sec-Fetch-Mode 为 navigate；
- Sec-Fetch-Dest 为 document、iframe 或 frame；
- User-Agent 含 Mozilla/（不区分大小写）；
- Accept 请求 text/html 或 application/xhtml+xml，明确 q=0 的媒体类型不算接受。

这包括常见 Chrome、Firefox、Safari 直接访问，以及浏览器内 fetch 和网页下载按钮。开启后请复制订阅 URL 或扫码到代理客户端中更新；面板登录、节点编辑和二维码生成不受该开关影响。浏览器扩展/WebView 或使用浏览器标识的原生客户端也可能被拦截，需要时关闭开关。

**这不是客户端身份验证或防盗链保证。** 请求头可修改，脚本和浏览器也可能绕过；空标识、curl 和普通原生客户端请求不会仅因没有浏览器特征而被拒绝。需要限制来源时使用订阅 IP 白名单；链接泄露时使用批量重置订阅链接。此功能不能解决 Cloudflare Under Attack 对客户端的挑战，也不改变 CF 配置。

关闭后恢复浏览器下载。开关不修改节点、客户端配置、用户授权或链接令牌。它保存在订阅索引的 blockBrowserDownloads 布尔字段，不包含在仅 YAML 的可移植备份中；缺失字段默认为 false，损坏的非布尔字段拒绝读取。原 IP 白名单 API 不会清除该字段。

## API 与测试

管理员 `GET /admin/api/subscription-browser-access` 返回 enabled；`PUT` 提交 `{"enabled":true}` 或 false，`X-Profile` 指定订阅。普通用户不能修改，沿用 HTTPS、来源与管理员认证检查。

验证覆盖 Go 全量、专项 race、默认/启用/关闭、GET/HEAD、多种浏览器请求头、常见原生客户端标识、权限、跨订阅隔离、重启与损坏设置。真实 Chromium 验证开关保存、所有可用客户端下载的浏览器拦截与无浏览器特征请求放行，以及六主题四宽度。原生客户端兼容性采用 HTTP 请求头模拟，未在 Android/iOS 各客户端实机联网验收。没有开启生产订阅的拦截开关进行测试。

# 服务器周期流量

v0.1.29 新增：服务器监控 → 点击服务器 → 周期流量。仅管理员可读写，不向公开探针 API 或普通订阅用户展示周期设置和长周期日明细。

配置首次周期起点（UTC）、每月/季度/半年/年，以及流量口径：入站、出站、双向累计之和、双向累计较大值。可填写每周期限额，单位 GiB（1024³ 字节），0 表示不设限。保存只改变统计设置，不开启后台采样；需要在“历史记录”中启用。

周期结束日不计入旧周期，边界均为 UTC 零点。原起点为 31 日时，短月使用月末，之后恢复 31 日；闰年 2 月 29 日的年周期在平年使用 2 月末。无需网页打开，查询时自动计算当前周期，不依赖定时清零任务。

页面展示：周期开始/结束、已观测用量、限额及剩余额度、达到限额提示、入站/出站、有效观测时长、周期已过时长、记录缺口次数及本周期日明细。达到限额只作页面提示，不停节点、不扣费，也不自动发送额外 Telegram 通知。

首次配置纳入目前保存的最近 30 天日汇总；更早的数据不可能补回。启用后额外保存最多 400 天日汇总，覆盖完整年周期；24 小时资源曲线和原 30 天历史接口保持原保留范围。停用周期统计会删除长周期日汇总，保留原 30 天记录；重新启用只能重新纳入现存 30 天。历史页面“清空并停用”会一并清除周期设置及长周期日汇总，操作前会确认。

这仍是服务器默认路由网卡的有效区间观测，不是服务商的完整账单、订阅计费或全部网卡统计。断线、停采、计数器重置、网卡变化、超过 90 秒或跨 UTC 日的区间不补算。缺口次数不覆盖所有停机时间，必须结合有效观测时长判断数据完整性；无采样不能解释为没有流量。不会采集新远端指标，也无需更新 Agent。

修改周期或口径会从已保存日明细重新统计，不重置真实网卡计数。数据保存在既有 monitor-history 目录中的服务器 JSON，和其他历史数据一并原子保存及备份。回退到不认识长周期数据的旧版本可能丢弃新增字段，降级前必须备份。

验证：月末/季度/半年/闰年边界、限额与四种口径、累计溢出、61 天持续采样与 400 天清理、重启、并发、删除、非法输入、管理员/普通用户隔离；真实 Chromium 保存、刷新、停用、六主题及三种宽度。长期采样使用受控数据模拟，不把测试流量写入真实服务器。

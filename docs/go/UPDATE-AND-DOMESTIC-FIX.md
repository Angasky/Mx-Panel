# v0.1.24：更新入口、旧网页与默认国内联网修复

## 已定位的问题

1. 登录后的更新提示代码仅处理旧版提交 SHA，Go 更新返回 manual=true 时被排除。新增管理员页非阻塞版本横幅，可进入版本维护或忽略单个版本；不会自动重启后台。
2. v0.1.23 及之前发布为 prerelease，GitHub releases/latest 入口返回 404。v0.1.24 改为正式 Latest 发布。Go 自身读取 releases 列表，本身支持预发布；因此预发布标签不是 Go 网页漏提醒的唯一原因。
3. 旧 service 未带 --admin-html，或指向数据目录 index.html 时，更新保留的旧 service 会继续加载旧网页。现在正式二进制优先加载同目录、VERSION 一致的网页。真正自定义的其他 HTML 路径仍保留，开发模式不改变。
4. MXIOC 默认 DNS 将未单列域名的请求发到绑定代理组的海外 DoH；CN 域名没有整体真实 IP 过滤；全局 STUN/UDP 拦截可影响实时通信；基础广告组默认 REJECT 存在误拦截可能。

## 默认配置修复

- 默认 nameserver 使用阿里/腾讯 DoH，新增 geosite:cn 国内解析策略。
- fake-ip 的原始默认过滤中增加 GEOSITE,cn,real-ip；海外服务的专用策略保持原样。
- 删除原模板内成套的全局 STUN/UDP 端口拒绝规则，不自动添加 DIRECT 端口规则；其流量继续按正常域名/IP分流。
- 基础广告组默认顺序改为 DIRECT、REJECT；仍可手动选择拦截。

启动时仅修复具有 MXIOC 特征策略组且 nameserver 完整匹配原默认值的订阅。用户自定义的 DNS、fake-ip 过滤、CN 解析策略保持；STUN 仅在原成套四条均存在时移除。节点、密码、其他规则、海外 DNS 策略不重置。修改走已有持久化事务，自动备份原 YAML 到数据目录 backups，并同步镜像文件；重复启动不重复修改。数据目录内的旧默认模板也在创建新订阅时进行同样处理。

## 老用户操作

服务器运行 mx-p 选择更新，或网页「设置 → 版本维护」检查并应用。更老、未提供 Go 更新入口的版本可用 README 一键安装命令重新获取安装器，其 auto 模式会识别已有 Go 安装并更新。

更新服务器后，手机必须重新拉取订阅，再断开并重连 VPN。Clash/Mihomo 需使用规则模式，不能全局代理。若客户端保留了旧的策略选择，先将「基础广告拦截」和「强力广告拦截」设为 DIRECT；必要时清理客户端 DNS/fake-IP 缓存。不要只刷新面板网页而不更新手机订阅。

完整 MXIOC 分流只随 Clash/Mihomo YAML 导入；vless/vmess 等裸链接及部分其他客户端导出不携带全部分流规则，客户端自己的路由设置仍需单独检查。本次未取得用户手机型号、客户端和具体故障 App，不能宣称已完成该手机的实机验收。

## 验证

全包 Go 测试、定向竞态检查；旧配置备份与镜像同步、幂等、自定义字段保护；旧启动参数的同版本 HTML 选择；真实 Chromium Go 更新横幅及主要用户流程。Mihomo v1.19.33 配置校验；在关闭 TUN 的隔离进程中故意选择不可用代理，测试国内 DNS、fake-IP 过滤及国内网站请求分流，不修改真实节点。

# 2026-11-08 订阅索引性能优化

## 修改

订阅列表、原始 YAML、快照、未变更保存每次查询都要读取订阅索引；此前通用解析之后又重新 JSON 序列化，再反序列化为 Profile。新增基于文件 SHA256 的单索引缓存，通用文档与类型化 Profile 解析结果均可复用。每次仍读取实际文件，不能仅凭 mtime/size 命中；错误读取或不同摘要立刻丢弃旧缓存。超过 1 MiB 的索引不保留，仍按原语义处理。

缓存访问在 Repository 锁内；通用文档和 Profile 的所有可变嵌套字段均返回独立副本。计量、过期与公开展示字段仍实时计算，未缓存权限判定或完整 HTTP 响应。保存仍按原子写入、镜像及备份机制执行。

## 针对性验证

`TestProfileCacheIsolationAndExternalChanges`：通用/类型化调用者不能污染缓存；包括 files、traffic、remoteNodes、failovers、plans、嵌套 lastEnforcedAt；超过浮点精度范围的 JSON 整数保持准确；同大小/mtime 外部替换刷新；坏 JSON 和删除索引拒绝旧缓存。

`TestProfileCacheTypedValidationAndAdmission`：即使通用解析命中缓存，也不跳过类型化字段校验；超过缓存上限的索引不驻留。

全包竞态记录 `artifacts/nov08-index-all.jsonl`；静态检查 `nov08-index-vet.log`；专项测试 `nov08-index-cache-tests.log`。真实内核使用上一轮兼容构建，开启 Reality 跨核和 Snell 复用。其他未变更包可能使用 Go 测试缓存。

## 最终回归及性能

全包竞态：508 个顶层测试，含子用例 1181 项通过、1 项跳过，无失败。跳过项仍是入口清单的外网更新检查。静态检查和双架构包校验通过。

同规格 11,040 次实测请求，0 失败。1000 节点、单并发、三轮平均毫秒：

| 操作 | 本轮 Python | 本轮 Go |
| --- | ---: | ---: |
| 订阅列表 | 1.56 | 1.10 |
| 节点快照 | 1.24 | 1.18 |
| 读取 YAML | 1.24 | 1.05 |
| 下载完整订阅 | 0.96 | 0.86 |
| 保存流量 | 1.17 | 1.04 |
| 真实节点修改 | 32.90 | 12.12 |
| 未变更节点保存 | 0.92 | 1.19 |
| 完整 YAML 保存 | 83.90 | 28.01 |

本轮八项中 Go 七项平均耗时低于 Python，未变更节点保存仍为 1.19ms 对 0.92ms。它仍保留全部镜像一致性检查，未通过删校验来换速度。快照/流量等小差距不应视为稳定胜出。两轮 Python 自身也明显变快，说明环境与调度有变化；不能把与上一轮 Go 的绝对时间差全部归因于代码。这里是后台 HTTP/存储测试，不代表公网代理吞吐或生产面板速度。

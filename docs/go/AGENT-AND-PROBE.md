# Agent、公开监控与 DNS 证书

## Agent 接入

硬件监控 → 选择服务器 → Agent 接入。支持 HTTP 上报、WebSocket 上报、自动回退，以及 HTTPS Pull。生成凭据后下载配置，保存到目标服务器 `/etc/mxioc-agent.json`，权限设为 `0600`。

```bash
curl -fsSL https://raw.githubusercontent.com/Angasky/Mx-Panel/main/deploy/quick-install-agent.sh -o /tmp/mx-agent-install.sh
sudo bash /tmp/mx-agent-install.sh
```

独立 Agent 包提供 amd64 / arm64 二进制，不需要 Python。安装前校验配置，启动失败恢复旧二进制与服务文件。进程启动不代表已连上面板；请回到 Agent 接入查看状态。撤销凭据立即拒绝新上报，并恢复 SSH 采样；需要在远端自行执行 `systemctl disable --now mxioc-agent` 停止 Agent。

自动模式优先 WebSocket，失败后使用 HTTP，每 5 分钟重试 WebSocket；每 15 秒采样，90 秒没有新样本显示过期。重置凭据后需重新下载配置；主控重启后等待下一次上报。Agent 可采样并管理本机授权的服务配置；现有节点部署和可视化入站/出站流程仍走 SSH。

Pull 要求有效的受信任 HTTPS 证书，地址为已登记主机的 `/metrics`。配置文件中的监听地址、证书及私钥路径需按实际环境调整。主控拒绝重定向、回环及链路本地地址；Pull 凭据在主控加密存储。推送模式凭据仅存摘要。

反向代理必须允许 WebSocket Upgrade，参考 [Nginx 示例](../../deploy/nginx.conf.example)。只开放 HTTP 上报也可运行自动模式。

## 公开监控

硬件监控 → 监控分享与只读 API。默认关闭。选择服务器、填写公开名称，可以生成私密链接，也可以勾选“允许无凭据公开访问”。需另行启用相应服务器的历史采样。

| 接口 | 用途 |
| --- | --- |
| `/sub/status-public` | 无凭据公开页面（必须显式启用公开模式） |
| `/sub/status/<token>` | 凭据控制的页面 |
| `/sub/status-api` | 当前指标 |
| `/sub/status-series?server=0&range=24h` | 历史，范围支持 `1h`、`6h`、`24h` |
| `/sub/status-ws` | WebSocket，每 5 秒推送当前指标 |

非公开模式的 API 和 WebSocket 请求须携带 `Authorization: Bearer <token>`，不接受查询参数令牌。`server` 使用状态接口返回的 `index`，不要自行按数组位置重编号。服务器被删除时对应历史返回 404。

白名单仅包含公开名称、展示索引、状态、采样时间、CPU、内存、收发速率。不会包含服务器内部 ID、IP、SSH 凭据或代理配置。公开页面提供 24 小时 CPU/内存曲线；缺失采样不连线。暂停、撤销或关闭公开访问后，已有 WebSocket 会在下一次推送前重新鉴权。资源采样失败不等同于代理服务离线。

## DNS 证书验证

新增节点 → TLS 模板 → 自动申请证书 → 选择验证方式：

- HTTP：保留原 TCP 80 验证方式。
- Cloudflare：`CF_Token`，需要目标区域 DNS 编辑和区域读取权限。
- 阿里云 DNS：`Ali_Key`、`Ali_Secret`。
- DNSPod：`DP_Id`、`DP_Key`。

DNS 验证不需要开放 80 端口，不要求关闭 CDN。凭据通过已固定主机指纹的 SSH 发送，保存在远端 root 专用 ACME 目录，供自动续期使用。主控不保存这些 DNS 密钥，也不返回可能包含密钥的远端签发日志。ACME 程序与 DNS 插件均固定提交和 SHA256。

已存在且有效的证书会复用，保留原续期方式；不会通过强制签发消耗 ACME 配额。只支持单个明确域名，不支持通配符。无实际 DNS 账户的环境只能验证脚本、权限边界与界面，不能据此宣称公网签发已实测。

## Agent 服务配置管理（v0.1.12）

Agent 接入 → 服务配置管理，支持本机明确授权的 Xray、sing-box、Nginx 服务：

- 读取配置、查询状态。
- 使用对应真实内核校验配置。
- 按读取时的版本应用配置；配置发生变化时拒绝覆盖。
- 自动保存上一份配置；启动失败自动恢复旧配置和服务。
- 手动恢复上一份配置，以及启动、停止、重启、重载。

HTTP、WebSocket、自动回退、HTTPS Pull 均可传递管理任务。主控任务和返回的配置加密保存在主控；Agent 回执目录仅 root 可读。任务 ID 在执行前写入持久回执，断线重传不会重复执行；执行中断会返回“结果未确认”，要求先检查服务与配置。轮换凭据取消旧的未完成任务；已发往远端且开始执行的操作无法通过撤销倒退。

默认生成的 Agent 配置仅监控。生成配置时可展开“授权 Agent 管理一个服务”，填写远端配置、程序绝对路径和 systemd 名称；勾选修改权限才允许校验自定义配置、应用、回滚及服务状态修改。也可在远端的 `0600` 配置中手动添加：

```json
{
  "targets": {
    "xray": {
      "kind": "xray",
      "config": "/usr/local/etc/xray/config.json",
      "binary": "/usr/local/bin/xray",
      "service": "xray",
      "writable": true
    }
  },
  "stateDir": "/var/lib/mxioc-agent"
}
```

以上是合并到现有 Agent 配置的片段，需保留 url、token、mode 等连接字段。配置及程序路径必须在远端已存在；不接收面板提交的任意路径或 shell 命令。配置文件最大 256 KiB，不能是符号链接。通过管理界面替换文件会保留原所有者和权限。

修改 targets 后重新执行 Agent 安装脚本，让 systemd 的可写目录同步本机授权。Nginx 授权应指向完整主配置文件；依赖的 include 文件不通过此页面修改，备份/回滚仅覆盖选定的单个配置文件。修改 Nginx 可能使当前管理连接短暂断开；请重新查询配置和服务状态确认结果。

“active”只表示 systemd 服务处于运行状态，并非代理节点连通性测试。该功能提供已有服务的配置与生命周期管理，不安装代理内核，也未将现有所有 SSH 可视化管理流程替换成 Agent。

从 v0.1.11 升级的旧采样凭据仍可采样，但启用服务管理前需轮换并重新安装 Agent 配置，绑定当前服务器身份。服务器地址、SSH 主机指纹等连接身份发生变化后也需要重新生成配置，避免旧 Agent 管理错误的机器。

## Agent TCP 连通探测（v0.1.13）

Agent 接入 → TCP 连通探测目标，填写公开名称、公网域名/IP 和 TCP 端口，再生成配置并更新远端 Agent。界面可设置三个目标，配置文件最多六个；默认不探测任何地址。

```json
{"probes":[{"name":"自有香港服务","host":"your-server.example.com","port":443}]}
```

Agent 约每 30 秒发起一次 TCP 建连，单目标超时 3 秒。时间从建立连接开始计量，不包含 DNS 解析耗时；失败记录不伪造为 0 ms。禁止内网、回环、链路本地、多播及共享地址；域名解析含不允许地址时整个目标拒绝探测。

监控 → 服务器 → TCP 探测，展示当前结果、24 小时曲线和已观测样本的失败比例。历史采样需在“历史记录”单独开启；暂停时不写历史，但 Agent 仍按本机配置探测。要停止探测，应移除远端 probes 并重启 Agent。更改目标地址时建议使用新名称，避免旧历史与新目标混淆。

启用监控分享后，所选服务器的探测名称、时间、成功状态和延迟会作为公开字段展示，不包含探测目标域名/IP/端口。接口：

- `/sub/status-api` 和 WebSocket 的 `tcpProbes` 字段。
- `/sub/status-series?server=<index>&metric=tcp&range=24h`；也支持 `1h`、`6h`。

TCP 建连失败比例不是 ICMP 丢包率，探测方向为 Agent → 指定目标，不是主控 → Agent，也不代表代理协议可用性。本功能不包含三网回程归属分析。

## 从面板自动部署 Agent（v0.1.14）

服务器监控 → Agent 接入 → 填写连接方式、可选服务授权和探测目标 → 生成配置 → **通过 SSH 自动安装**。

面板使用已有 SSH 账号、提权方式与固定主机指纹。远端自动识别 amd64/arm64，下载固定 SHA256 的 Agent v0.1.13，先验证配置，再替换 `/etc/mxioc-agent.json` 并安装 systemd 服务。v0.1.13 已包含服务管理与 TCP 探测能力；本次更新的是主控部署流程，无须为了版本号重复升级 Agent。

部署前保存原 Agent 配置、二进制及服务文件；安装失败尽力恢复旧文件及服务启用/运行状态，恢复失败会明确报告。部署不安装代理内核，不自动签发 Pull 证书，也不会修改代理配置。授权的配置文件和程序必须事先存在，Pull 模式的 TLS 证书也必须已部署。

部署任务保存在服务器任务记录中，关闭弹窗不取消任务；重新打开 Agent 接入 → 部署任务可以查看。重复提交相同配置在原任务成功后返回原任务，不重复安装。需要重新部署时先轮换配置；安装期间禁止轮换或撤销，以避免远端刚安装的凭据立即失效。

任务成功仅表示安装脚本和 systemd 启动检查通过。弹窗另行显示 Agent 是否已向主控上报；未连接时检查面板域名、有效 HTTPS 证书、反向代理和远端网络。主控重启或 SSH 中断可能无法确认远端最终状态，任务不会自动重放，应核对远端后重试。

自动部署始终使用当前面板 HTTPS 地址，拒绝其他域名及不匹配的服务器/令牌。配置通过 SSH 标准输入传输，不写入主控任务日志；任务日志仅输出固定状态信息。


## 地域与续费记录（v0.1.14）

服务器监控 → 选择服务器 → 地域与续费，填写地域、服务商及 HTTPS 官网链接、UTC 到期日期、价格、币种和周期。监控卡片会显示地域和服务商，到期前 30 天及已过期状态会突出提示。

默认仅管理员可见。开启“在已启用的监控分享页/API 中公开这些信息”后，已选择分享的服务器才会展示这些字段；该开关不会自动开启监控分享。公开页面、状态 API 和实时推送使用相同规则。撤销公开或清空信息后，下次读取/推送即不再返回。

这些信息由管理员填写，不自动推断地域，不自动扣费/续费，也不进行汇率换算。价格不是订阅套餐计费。日期以 UTC 自然日为准。

## ICMP Echo 与丢包观测（v0.1.15）

先升级主控到 v0.1.15，再升级远端 Agent。Agent 接入的目标配置现在可选择 TCP 或 ICMP；旧配置没有 method 时保持 TCP 行为。示例：

```json
{"probes":[{"name":"自有公网服务器 ICMP","host":"your-server.example.com","method":"icmp"}]}
```

ICMP 不使用端口。每轮向解析得到的第一个公网地址发送一个 Echo，支持 IPv4/IPv6，以随机标识、序列号、负载及源地址核对回包，超时 3 秒。需要 Linux 原始套接字权限（通常 root / CAP_NET_RAW）；安装器的 root 服务可使用已有权限，容器是否允许取决于容器配置。

网络探测页面按目标名称和协议分别展示。ICMP 的“未回包比例”仅以实际发出的 Echo 为分母；没有套接字权限、DNS 失败、地址拒绝、发送失败与主动取消不计入。未回包可能来自过滤或限速，不代表代理不可用；本功能不是三网回程分析。

状态 API 新增 `icmpProbes`；原 `tcpProbes` 仅含 TCP。历史使用 `metric=icmp`，原 `metric=tcp` 保持仅返回 TCP。每个结果包括 method、sent、error、ok、milliseconds；没有成功回包时 milliseconds 为 null。目标地址仍不公开。

v0.1.15 的自动部署已固定为新 Agent v0.1.15 及对应 SHA256。所有归档规范化时间和所有者，使同一源码重建的 Agent 包保持稳定校验值。

### 发布构建元数据（v0.1.16）

发布构建禁用 Go 自动嵌入的工作区 VCS 信息，避免与 Agent 无关的主控提交或工作区脏状态改变 Agent 二进制及包校验值。归档已规范化时间、顺序及 UID/GID。同源码、工具链和构建参数下可重建；不承诺跨 Go 版本得到相同哈希。v0.1.16 面板自动部署仍固定使用 v0.1.15 Agent；新包的 Agent 功能保持不变，已有 Agent 无需升级。

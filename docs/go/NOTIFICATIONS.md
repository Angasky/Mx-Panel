# Telegram 通知中心

入口：管理员「设置 → 通知中心」。默认关闭，普通用户不能读取或修改配置与记录。

填写自己的 Bot Token 和数字 Chat ID（群 ID 通常为负数），先与机器人私聊或将其加入目标群，再启用。点击保存并启用即允许面板向该会话自动发送符合条件的提醒。Token 加密存储，读取只返回是否已配置；留空保留原值，勾选清除可删除。

## 已支持

- 连续监控失败与采样恢复：默认连续 3 次，可设置 2–20 次；仅处理已启用历史监控的服务器。采样超过 120 秒没有更新时视为未知，不报恢复。采样失败不证明代理服务已经离线；停用/删除服务器不触发恢复通知。
- 订阅流量阈值：默认已用额度达到 90%，可设置 1–100%；只检查已配置额度的订阅。
- 订阅到期与服务器续费：默认提前 7 天，可设置 1–30 天；依赖已有订阅到期时间及服务器元信息。日期采用 UTC，已经到期也会提醒。

每轮历史采样结束后检查一次，正常约 30 秒；不会为通知增加远程 SSH 或重启节点。同一异常持续期间不重复通知，恢复后再次异常可重新提醒；到期日期修改后重新判断。首次启用会提醒已经满足条件的项目，不追溯历史日报。

## 投递与记录

每轮最多投递一条消息，失败按指数退避，尊重 Telegram 的 retry_after（最多一天），最多 8 次，最终失败可在记录中看到。改变接收人、Token、通知类别或关闭通知会取消尚未发送的记录。配置失败不会覆盖旧配置。

最近 200 条记录和去重状态持久保存在数据目录 notifications.json，权限 0600，Bot Token 使用既有 credentials.key 加密。备份时应同时保留这两个文件。记录只包含对象名称、提醒信息、状态和通用错误，不包含节点地址、订阅链接或 Token。

队列与记录合计保留最近 200 条，超出会淘汰最早记录；不承诺无限积压保存。发送成功和本地状态落盘之间崩溃可能重复投递一次；网络超时也可能出现 Telegram 已接收但客户端未确认的情况。关闭通知不能撤回已发出的消息。关闭再开启不会重发仍处于同一异常的已记录提醒。

尚未支持日报、探测延迟/丢包阈值、“我已续费”回调和多接收人。真实 Bot 的投递需由使用者配置验证；开发验收使用模拟接口，不向真实用户发送测试消息。

# Telegram 通知中心

入口：管理员「设置 → 通知中心」。默认关闭，普通用户不能读取或修改配置与记录。

填写自己的 Bot Token 和数字 Chat ID（群 ID 通常为负数），先与机器人私聊或将其加入目标群，再启用。点击保存并启用即允许面板向该会话自动发送符合条件的提醒。Token 加密存储，读取只返回是否已配置；留空保留原值，勾选清除可删除。

## 已支持

- 连续监控失败与采样恢复：默认连续 3 次，可设置 2–20 次；仅处理已启用历史监控的服务器。采样超过 120 秒没有更新时视为未知，不报恢复。采样失败不证明代理服务已经离线；停用/删除服务器不触发恢复通知。
- 订阅流量阈值：默认已用额度达到 90%，可设置 1–100%；只检查已配置额度的订阅。
- 订阅到期与服务器续费：默认提前 7 天，可设置 1–30 天；依赖已有订阅到期时间及服务器元信息。日期采用 UTC，已经到期也会提醒。

每轮历史采样结束后检查一次，正常约 30 秒；不会为通知增加远程 SSH 或重启节点。同一异常持续期间不重复通知，恢复后再次异常可重新提醒；到期日期修改后重新判断。首次启用会提醒已经满足条件的项目，不追溯历史日报。

## 投递与记录

每轮最多投递一条消息，失败按指数退避，尊重 Telegram 的 retry_after（最多一天），最多 8 次，最终失败可在记录中看到。改变接收人、Token、阈值、通知类别或关闭通知会取消尚未发送的记录。配置失败不会覆盖旧配置。

最近 200 条记录和去重状态持久保存在数据目录 notifications.json，权限 0600，Bot Token 使用既有 credentials.key 加密。备份时应同时保留这两个文件。记录只包含对象名称、提醒信息、状态和通用错误，不包含节点地址、订阅链接或 Token。

队列与记录合计保留最近 200 条，超出会淘汰最早记录；不承诺无限积压保存。发送成功和本地状态落盘之间崩溃可能重复投递一次；网络超时也可能出现 Telegram 已接收但客户端未确认的情况。关闭通知不能撤回已发出的消息。关闭再开启不会重发仍处于同一异常的已记录提醒。

v0.2.17 已支持可选的“我已续费”回调（见下文），仍不支持多接收人。真实 Bot 的投递需由使用者配置验证；开发验收使用模拟接口，不向真实用户发送测试消息。


## v0.1.22：每日汇总

在通知中心勾选「每日汇总」，选择 UTC 发送小时（界面同时显示北京时间）。默认 UTC 01:00，即北京时间 09:00；该选项默认关闭。到时在下一轮巡检排队发送前一个 UTC 自然日的汇总，投递受队列与重试影响，不保证整点抵达。

内容包括：服务器网卡 RX/TX 观测流量、拥有有效流量区间的服务器数量、有效区间累计服务器小时、记录的采样缺口，以及生成时的订阅数量、额度用尽和已到期数量。订阅部分明确是当前状态快照，不是昨日新增订阅用量；未采样的区间不补算，也不能当作零流量的证据。

「预览日报」只读取和展示数据，不发送、不排队、不消耗当天发送标记；无需开启通知。管理员以外无法预览。

日报排队标记持久化，重启或同日反复巡检不会重复排队；服务器停机多日后只处理最近一个已结束自然日，不补发所有历史日报。首次启用且已超过所选小时会在下一轮生成。修改设置导致已排队日报取消后，同一统计日不会自动重新排队。

## v0.1.22：延迟与丢包告警

开启「延迟 / 丢包告警及恢复」，设置成功样本平均延迟阈值（默认 300 毫秒）和失败比例阈值（默认 20%）。使用服务器现有 Agent 探测历史，需要配置探测目标并开启历史采样；无需更新 Agent。

- 窗口为最近 5 分钟，每个目标及协议独立计算，至少 5 个有效样本；延迟只计算成功且有延迟值的样本。
- TCP 统计连接失败比例（含 DNS 等连接准备失败），不能称为网络丢包。
- ICMP 只把实际已发送的 Echo 样本作为分母；无权限、DNS 失败等未发出的样本不算丢包。
- 最新记录超过 120 秒、样本不足、最新 ICMP 未发出时为未知；保留已触发告警，不误报恢复。已删除目标/停止历史采样不会产生恢复通知。
- 指标达到阈值触发一次，仍超过阈值期间不随数值变化反复刷屏；满足样本要求且低于阈值才发送恢复。重新超标可再次告警。

验证使用模拟网络样本与 Telegram 响应，覆盖阈值边界、过期/缺失/重复/未发送样本、恢复去重、UTC 日界线、旧配置兼容及管理员权限；没有向真实会话发送测试消息。

## v0.1.31：续费后旧提醒清理

服务器可在「地域与续费」快速登记新到期日。下一轮巡检取消尚未发送且已不符合当前日期的服务器/订阅到期消息；已发送和正在投递的消息不能撤回。该版本尚未实现内联续费回调，v0.2.17 已补齐，详见 [快速登记续费](SERVER-RENEWAL.md)。


## v0.2.17：Telegram 续费按钮

在通知中心开启「在服务器续费提醒中添加我已续费按钮」，填写允许操作的 **Telegram 用户 ID**，多个用逗号分隔，最多 20 人。用户 ID 是正整数，群 Chat ID 不能用作操作用户授权。必须开启通知和到期提醒；关闭其中任一项会自动关闭续费按钮。旧配置默认关闭，升级不替用户启用。

使用专用 Bot：面板每 5 秒通过 getUpdates 获取最多 20 条按钮更新，正常响应可能受网络、其他操作和重试延迟影响。不需要额外公网回调地址，不设置或删除 Webhook。若 Bot 正在其他程序中轮询或已设置 Webhook，Telegram 可能返回 409；通知中心显示冲突并退避。不要与其他机器人程序共用 Token。

只给新增的服务器续费提醒附带按钮，服务器需已保存有效到期日期及月/季度/半年/年周期。已有已发送提醒不会自动重发；按钮随最近 200 条通知记录保存，生成后最多 7 天有效，记录淘汰也会使按钮失效。修改通知设置会撤销旧按钮，单纯不改变设置的保存不撤销。订阅到期提醒不提供此服务器操作。

1. 授权用户在配置的目标私聊或群聊点击「我已续费 · 预览登记」。
2. 消息展示原日期、新日期（UTC）、公开状态和只登记不支付的说明。
3. 原操作用户 5 分钟内点击「确认已付款 · 登记新日期」，或取消。多名授权人同时预览时，只有最近一次预览有效。
4. 成功后更新原消息并移除按钮，面板最近通知显示操作用户 ID、登记时间和前后日期。

从原到期日延长一个已保存周期，月末处理与网页登记相同；需要从今天起算或纠正日期时，请使用网页入口。只更新服务器到期元信息，不执行服务商支付、不延长订阅、不重置流量、不重启节点。

服务端同时核对目标聊天、用户白名单、随机按钮标识、预览用户、有效期和当前元信息摘要。匿名/未授权/跨聊天/旧按钮不能写入；并发、重启和重复回调不会重复延长。同一次登记在元信息已保存但通知状态尚未保存时中断，重试会因摘要改变而拒绝，需到面板核对；不会再次延长。回执网络失败不回滚已保存日期，错误保留在通知中心，直到后续回执成功或配置改变。元信息和通知记录是两个原子文件，不宣称跨文件事务。

测试使用隔离数据和模拟 Telegram：按钮发送、预览/确认/取消、授权隔离、过期/被编辑的记录、并发及重启窗口、偏移量持久化、409 退避、配置在请求中改变。真实 Chromium 验证配置保存/拒绝、普通用户禁止访问、六主题四种宽度；测试进程外发网络被隔离，未向真实会话发送验收消息。
